# 三个重点案例

这三个项目分别呈现我的规则设计、人物到玩法的转译，以及交互与创作流程的思考。

## 国象 × 将棋

**问题：两套各自成立的规则，能不能在同一张棋盘上相遇？**

我长期喜欢棋类，这是我开始使用 Claude Code 后做的第一个作品。我把国际象棋与将棋放进 9×9 棋盘，协调不同棋子的走法，以及将棋的打入、升变等机制。项目提供本地同屏与联机大厅。

这件事让我发现：提出“把两种棋合起来”的点子很快，但真正的设计发生在规则冲突时。棋盘大小、棋子能力和特殊机制，都需要作出具体选择。现在的版本仍在探索平衡，部分特殊规则尚未实现；我没有把“能玩”当作“已经平衡”。

下一步我想把规则变体做成可重复比较的实验：保留版本、记录对局，先找出不合理的机制，再尝试设计更合适的人机。

**证据：** [项目、规则与运行方式](https://github.com/xing0325/chess-shogi)。仓库支持查看实现，平衡性判断还需要更多试玩数据。

## Slay the Curiosity

**问题：熟悉的人的性格，怎样转译成玩家能感受到的机制？**

我受到《杀戮尖塔》的启发，参与制作了以社区老师、同学等熟悉人物为灵感的卡牌游戏。我最投入的部分，是把人物特征写进角色、技能与卡组，让角色不只是在名字和头像上有所不同。

社区试玩和后来交接给同学的经历，让我体会到玩法设计、反馈与共同创作之间的关系。它也帮助我确认，比起单纯把界面搭出来，我很喜欢思考“这个人物为什么应该这样玩”。

我的说明主要覆盖早期设计与制作。下方仓库还包含接手同学和后续开发的成果，不能把全部当前功能归为我的独立贡献。

**证据：** [现项目仓库与开发记录](https://github.com/xing0325/xing0325/blob/main/cases/SLAY.md)。角色创作动机、早期试玩与交接经历来自我的个人复盘。

## 拾集 pick.

**问题：一个人不愿开始的整理任务，能不能通过交互变得容易进入？**

我把散落的作品资料变成卡片，用滑动完成取舍，再即时写下兴趣关联和学习收获。待定、撤销与导出帮助我保留退路。我把它叫作“皇帝批奏折模拟器”。

截至2026年10月3日，我实际用它完成了95个原始条目的筛选，留下89条非空批注；本主页的项目关系和兴趣分类就是这次使用的产物。这些条目包括版本、归档和资料集合，不代表95个独立产品。

这让我更清楚地意识到：交互设计不仅是视觉效果，也可以改变任务的节奏和开始行动的阻力。目前它是本地自用原型，尚无多用户效率验证，也没有公开试玩地址。

**证据：** [交互说明与使用结果](PICK.md)。公开页面展示设计和复盘，原始目录含私人材料，没有整体公开。
